# Projects — как Unity Hub, но внутри редактора

Проектов на scrap у одного человека уже несколько, и каждый собран против
своей копии движка: Dacha в `../runity`, её копии для профилирования и
физики — в worktree'ах, gamekit — в третьем. Открывать их приходилось
через File › Open с поиском сцены, а понять, против какого движка
собрана игра, можно было только из `Cargo.toml`. Unity Hub решает то же
самое: список проектов, версия движка у каждого, открыть одним кликом.

## Что берём

1. **Список — личный, а не проектный.** `projects.ron` в папке настроек
   редактора (`~/Library/Application Support/scrap` на macOS, там же
   `preferences.ron`): пути, закрепы и когда проект открывали последний
   раз. Всё остальное — имя, ветка, движок — читается из проекта заново
   при каждом показе, так что список не врёт после `git checkout` или
   правки `scrap.ron`. Проект попадает в список, когда его открывают в
   редакторе — со старта или через File › Open.
2. **Версия движка — коммит копии.** Пока движок меняется каждый день,
   номер версии ничего не говорит: у всех проектов `engine: "0.1.0"`.
   Правда — строка `scrap-engine` в `Cargo.toml` игры. Для `path = …`
   hub находит корень репозитория или worktree, в котором лежит путь, и
   показывает его коммит, ветку и звёздочку при незакоммиченных правках
   (`f85a8006 claude/dacha-port*`). Для git-источника — коммит из
   `Cargo.lock`. Если копия не та, из которой собран этот редактор,
   строка желтеет: «not this editor's».
3. **Экран Projects в редакторе.** File › Projects… и при запуске
   приложения (из Dock, hop или лаунчера) без сцены в аргументах. На старте
   за ним ничего не открыто: проект выбирают до того, как редактор что-то
   загрузил, и закрыть экран, пока не выбран проект, нельзя — Esc и клик
   мимо ничего не делают. Закреплённые сверху, дальше по
   времени открытия. Поиск по имени, папке, ветке и коммиту. Клик — старт
   сцена проекта (`game.start_scene`, иначе первая). Add… — проект или
   папка, в которой проекты ищутся на два уровня вниз. New… — форма на том
   же экране: имя, папка (по умолчанию рядом с последним открытым
   проектом, но не внутри движка) и с чего начать — пустой проект с
   набором basic, full или bare, или копия одного из примеров движка
   (`scrap new --template`: graphs, kitchen, kitchen-web, valley — CI их
   собирает, так что шаблон — работающая игра). Игра нового проекта
   собирается против этой копии движка.
4. **То же из командной строки.** `scrap projects [--json]`,
   `scrap projects add|forget|pin|unpin`. Экран и команда зовут одни
   функции `scrap_cli::hub`.
5. **Смена проекта в том же окне.** Открыть сцену другого проекта
   (с экрана или File › Open) теперь значит: остановить его игру, забыть
   слежку за шейдерами прежнего, поднять раскладку панелей нового
   (`.scrap/studio.ron`) и сказать в Console, если игра проекта собрана
   против другой копии движка.

## Чего не берём и почему

* **Установку версий движка.** Unity Hub качает редакторы; у нас версий
  нет, есть копии репозитория, и их делает git. Когда появится поезд
  релизов (DNA, постулат 3, «официальные модули идут одним поездом»),
  hub будет ставить тег в `~/.scrap/engines/<версия>` — это следующий
  этап, не этот.
* **Запуск редактора той копии, против которой собрана игра.** Сейчас
  проект открывается этим редактором, а расхождение только
  подсвечивается. Форматы сцен между соседними коммитами почти всегда
  совместимы, а сборка редактора другой копии — минуты. Когда
  расхождение начнёт ломать проекты, открытие будет собирать и запускать
  `scrap-studio` из той копии — с тем же окном прогресса, что у
  лаунчера (`tools/studio-open.sh`).
* **Отдельное приложение, как uhub.** Второй UI-стек рядом со
  `scrap-ui`, только под macOS и без headless-тестов. Экран в редакторе
  проверяется так же, как остальные панели.

## Ответы постулатам

* **1. Скорость итерации.** Открыть проект — клик вместо поиска сцены в
  файловом диалоге. Список читается на отдельном потоке (git спрашивается
  по нескольку раз на проект), экран не ждёт его.
* **2. Git.** Список — личный файл вне проектов, в git не попадает и
  конфликтов не создаёт. В проекте ничего не меняется, кроме того, что
  уже меняло открытие (раскладка в `.scrap/`). Ветка проекта и коммит
  движка видны на каждой строке.
* **3. Модульность.** Не касается: экран — часть редактора, модулем не
  выключается, как не выключается File › Open.
* **4. Сеть.** Не касается.
* **5. Агенты.** Всё, что умеет экран, умеет `scrap projects --json`:
  список с ветками и движками, добавить, забыть, закрепить. Экран держит
  headless-тесты: `the_projects_screen_lists_pins_forgets_and_opens` —
  закреп поднимает строку, пропавшая папка говорит об этом, поиск
  фильтрует, клик открывает проект в этом окне;
  `the_editor_starts_on_the_projects_screen_and_new_makes_a_project` —
  старт без проекта, Esc не закрывает, New делает копию примера и
  открывает её.
* **6. Производительность.** Не касается кадра: экран строится один раз
  при открытии, и строки перестраиваются только на ввод в поиск.
* **7. Opinionated.** Один список, одна сортировка (закреп, потом
  недавние), никаких настроек колонок.
* **8. Батарейки.** Человек без терминала создаёт, находит и открывает
  проекты, не выходя из редактора.

## Этапы

1. ✓ Список, `scrap projects`, экран, смена проекта в окне.
2. ✓ Старт на экране без открытого проекта; New с выбором набора и
   примера.
3. Открытие редактором той копии движка, против которой собрана игра
   (сборка с прогрессом, как у лаунчера).
4. Версии движка поездом релизов: `~/.scrap/engines/`, установка тега,
   смена движка у проекта.
