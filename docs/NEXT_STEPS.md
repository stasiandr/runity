Решения от 2026-09-23 («Голое ядро и наборы», «Модуль — исходник»,
«Видеокарта — модуль `gpu`», «Геометрия — базовый модуль» и остальные).
Сегодня `runity` — один крейт, и рендер, сеть, UI, анимация и навигация в нём
без флагов.

- [ ] Разрезать `runity` на ядро и модули-крейты
  - [ ] Первой — физика: шов почти готов (`physics` уже фича), на ней
        проверяются манифест и фазы
  - [ ] `geometry`: меш как данные, границы, лучи, простые фигуры;
        `MeshAsset` уезжает из ядра
  - [ ] `gpu`: устройство, поверхность, текстуры, шейдеры
  - [ ] `render` и `ui` поверх `gpu`
  - [ ] Навигация, анимация, звук, сеть, Steam, террейн, scatter, блокаут —
        каждый своим модулем
  - [ ] Голое ядро собирается и проходит тесты без GPU (сервер, тест, MCP)
- [ ] Модуль как единица поставки
  - [ ] Манифест модуля: имя, версия, совместимость с ядром, зависимости, что
        приносит в рантайм и что только в редактор
  - [ ] Модуль без кода — только ассеты
  - [ ] Список модулей проекта в `runity.ron`; зависимости `Cargo.toml`
        выводятся из него; `check` ловит расхождение
  - [ ] Типы ассетов регистрируют модули
  - [ ] Официальные модули идут поездом релизов с ядром
- [ ] `runity new`: голый, базовый, полный набор или темплейт
  - [ ] Состав базового набора — из мерки Flappy Bird (картинка, ввод, счёт,
        звук, столкновения); решить, физика в нём или пересечения в `geometry`
  - [ ] Темплейты — проекты в репозитории движка, CI их собирает
- [ ] Цикл по фазам PlayerLoop: инициализация, начало кадра, FixedUpdate
      (`step`), Update, LateUpdate, конец кадра с рендером (`frame`); модуль

- [ ] Ввод как Unity Input System: в ядре — события устройств; действия, карты,
      привязки, схемы управления — модуль; `input.ron` — его частный случай
- [ ] Компонент отключённого модуля хранится текстом, переживает сохранение,

- [ ] Редактор как набор модулей
  - [ ] Голый редактор: иерархия, инспектор, Project, консоль
  - [ ] Точки расширения: панели, меню, инструменты, гизмо, импортёры, формы

  - [ ] Действие модуля регистрируется один раз — его видят меню и агент
        (MCP-инструмент)
- [ ] Рендер из отключаемых проходов: каждый проход выключается при сборке

# Перенос Dacha Simulator

Что нужно, чтобы `~/personal/dacha-simulator` (Unity 6, URP, до 16 игроков,
Steam) жил на runity. Порядок — по риску: сначала то, что может сделать
перенос бессмысленным.

## 1. Физика выдерживает «Дачу»

Геймплей «Дачи» — это поведение PhysX: `MovePosition`, правило трения,
нормали контактов как правда о земле, ломающиеся суставы. На rapier это
будет ощущаться иначе.

- [ ] Несколько изолированных физических миров в одном процессе (мир на пира,
      как в стенде «Дачи»)
- [ ] Физический стенд: 13 сценариев «Дачи» (`Assets/Tests/PlayMode/PhysicsBench/`)
      на лестнице ухудшающихся связей, её метрики — правда против одиночного
      прогона, ошибка картинки, детекторы запуска, байты в секунду
- [ ] Сравнить с PhysX и решить, выживает ли ощущение (если нет — открытый
      вопрос: Jolt, stack.md «Физика»)
- [ ] Суставы, которые ломаются: порог силы и событие о разрыве
- [ ] Пружины и приводы как у `ConfigurableJoint` и `SpringJoint`, пределы и
      цель пружины, меняемые во время игры
- [ ] Смена «динамическое ↔ кинематическое» с сохранением скорости
