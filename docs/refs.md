# Ссылки: всё, что может быть ссылкой, — ссылка

Карточка к решениям DNA «Ссылки на ассеты — ID плюс имя» и «Всё, что может
быть ссылкой, — ссылка» (2026-09-23).

## Что сейчас

Стабильные ID у движка уже есть, но форматы их почти не хранят.

* **Сущности** — хорошо. `EntityId` в сцене, суставы, `Follow`, оверрайды
  префабов, сейв и сеть идут по ID. Компонент игры ссылается на сущность
  через `EntityRef` с пикером в инспекторе.
* **Ассеты** — плохо. `AssetId` выдаётся при импорте и лежит в `.rimport` и
  `.rasset`, а библиотека умеет искать по нему. Но сцена, префаб, вариант,
  сейв и сетевое сообщение называют модель, материал и префаб по имени
  файла. Переименование мимо движка рвёт ссылки. Два `rock.glb` в разных
  папках затирают друг друга в библиотеке, собранной плоско по имени файла.
  У префабов, сцен, графов анимации и экранов нет ID вообще.
* **Записи конфигов** — по именам: слои из `layers.ron`, действия ввода,
  ключи строк `@menu.play`, параметры графа анимации.

## Модель

* **У каждого файла-ассета есть сайдкар с ID.** `.rimport` уже есть у
  моделей, текстур, звуков и материалов. Его получают и префабы, сцены,
  графы анимации и экраны. Одно правило вместо двух, как `.meta` в Unity.
  Файл без сайдкара (скопирован руками, пришёл из git без него) получает
  его при следующем `sync`. Импортируемый исходник, переехавший без
  сайдкара, находится по хэшу содержимого. У текстовых ассетов — сцены,
  префаба, графа, экрана — в сайдкаре только путь и ID, без хэша: сцена
  меняется с каждым сохранением, и хэш тащил бы её сайдкар в каждый дифф.
  Такой файл, переехавший в другую папку мимо редактора, находится по
  имени файла. Файл, переименованный мимо редактора, находит ссылка: если
  по ID ничего нет, она ищет по имени, которое хранит рядом, и при
  сохранении дописывает новый ID.
* **Ссылка на ассет — ID плюс имя:** `model: ("rock", "fc5513a0…")` — имя и ID парой. Имя первым, чтобы строка читалась в диффе, а пара, а не структура, — чтобы сущность в одну строку оставалась в одну строку. Движок ищет по
  ID. Имя — подсказка, и при сохранении движок приводит его к нынешнему
  имени файла.
* **Имя без ID принимается.** `model: "rock"`, написанное человеком или
  агентом, находится по имени и при первом сохранении дописывается ID.
  Так руками писать сцену по-прежнему можно (постулат 5).
* **Библиотека — по ID.** Собранный ассет называется по ID, а не по имени
  исходника, поэтому одинаковые имена в разных папках не сталкиваются.
  Одинаковые имена остаются неоднозначными только для ссылки без ID, и
  `check` это называет.
* **Типизированные ссылки для компонентов игры.** Кроме `EntityRef` —
  `AssetLink` по видам: модель, материал, префаб, звук, текстура, сцена.
  Вид регистрирует модуль, который этот ассет приносит: ядро не знает
  слова «меш» (решение «Голое ядро»). Трассировщик форм видит тип ссылки
  по имени, и инспектор показывает поле пикером: список ассетов этого
  вида, перетаскивание из Project, «пусто».
* **Рантайм — тоже по ID.** Префаб в сейве и в сетевом `Spawn`, стартовая
  сцена в `runity.ron` — ID плюс имя. Сетевому сообщению это ещё и короче.
* **Записи конфигов получают ID.** Слой, ключ строки, параметр графа
  анимации — запись с ID и именем. Сцена ссылается на слой ссылкой, экран
  на строку — ссылкой. Код игры называет действия ввода и параметры через
  константы, которые движок генерирует из файла, как Input System в Unity
  генерирует класс: опечатка — ошибка компиляции, а не тихий промах.

## Что остаётся именем — и почему

Это записанные исключения, а не умолчание.

* **Встроенные ассеты движка** (`builtin:cube`). Их именует движок, и имя
  — их идентичность: переименовать их может только релиз движка.
* **Ключи внутри одного файла.** Состояния графа анимации (`from`, `to`,
  `start`), `id` элемента экрана. Цель и ссылка лежат в одном файле, и
  переименование в редакторе переписывает их одной правкой. Код игры
  называет элемент экрана через сгенерированную константу, как действие
  ввода.
* **Имя типа компонента** (`components: { "door": … }`). Зарегистрированное
  имя и есть идентичность типа в коде. Переименование типа — правка кода.
* **Клипы внутри модели.** У клипа нет своего файла: его имя внутри модели
  и есть его идентичность, как имя анимации в glTF. Граф анимации называет
  клип по имени, а редактор даёт выбрать его из клипов модели и `check`
  называет клип, которого у модели нет.
* **Пользовательские файлы редактора** (`.runity/editor.ron`,
  `studio.ron`). Они не коммитятся и никому не передаются.

## Ответы постулатам

1. **Скорость итерации.** Переименование больше не переписывает сцены:
   правка одного файла, а не всех, кто его называет. Поиск по ID — хэш,
   как и по имени.
2. **Git.** В диффе видно и имя, и ID. Переименованный ассет — это переезд
   файла и его сайдкара, без правок в сценах. Имя-подсказка догоняет при
   следующем сохранении сцены, и это одна строка. Мёрдж по ID надёжнее, чем
   по имени: две ветки, переименовавшие разное, не ломают ссылки друг
   другу.
3. **Модульность.** Виды ссылок регистрируют модули. Ядро знает только
   «ассет с ID», «сущность с ID» и пикер.
4. **Сеть.** `Spawn` называет префаб по ID: короче и не зависит от того,
   как файл называется у другого участника.
5. **AI.** Агент пишет имя, движок дописывает ID. `check` называет висящую
   ссылку со «did you mean». Пикеры — те же действия для агента.
6. **Производительность.** Ничего не дорожает: разрешение ссылки — поиск
   в хэш-таблице, как сейчас по имени.
7. **Opinionated.** Одно правило: у каждого файла-ассета есть сайдкар, всё,
   что называет другое, — ссылка. Исключения перечислены выше.
8. **Батарейки.** Пикеры, перетаскивание и `check` работают для любого
   поля-ссылки в любом компоненте игры без кода в редакторе.

## Риски

* **Материалы.** `MaterialRef` в сцене трогает сессия, которая делает
  рендер и материалы. Перевод материала на ссылку делаем вместе с ней,
  последним из полей сцены.
* **Миграция.** Сцены и префабы примера переписываются: имена становятся
  ссылками. Сохранение, сохраняющее текст (решение о сохранении сцен),
  должно писать ссылку в строку как есть, не трогая остальное.
* **Сайдкары у сцен и префабов** удваивают число файлов в этих папках, как
  `.meta` в Unity. Это цена одного правила.

## Этапы

1. **ID у каждого ассета.** Сайдкары для префабов, сцен, графов и экранов.
   Библиотека по ID; одинаковые имена в разных папках не сталкиваются.
   Сделано (2026-09-23).
2. **Ссылки в сцене.** `AssetLink` (имя плюс ID) для `model`, `prefab`,
   оверрайдов и базы варианта; чтение старых имён; сохранение дописывает
   ID и освежает имя; `rename` больше не переписывает сцены. Модель,
   префаб и материал сделаны (2026-09-23; встроенный материал остаётся
   именем, `builtin:` — тоже): сцена при
   открытии получает ID и нынешние имена (`refs::settle`), сохранение их
   пишет, меш и префаб ищутся сначала по ID, `check` принимает ссылку по ID
   с устаревшим именем, а одинаковые имена называет ошибкой только для
   строки без ID.
3. **Ссылки в компонентах игры.** Виды `AssetLink`, пикеры, перетаскивание
   из Project, `check`.
4. **Рантайм.** Сейв, сеть, стартовая сцена — по ID.
5. **Конфиги.** Слои, ключи строк, параметры графа анимации — записи с ID;
   константы для кода игры.
