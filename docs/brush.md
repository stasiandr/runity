# Браши с вычитанием — как в Hammer и TrenchBroom

Карточка к пункту 5 обзора инструментов дизайнеров
(`docs/history/2026-09-designer-tools-review/report.md`): любимый блокаут
левел-дизайнеров — браши с вычитанием. Поставил коробку, вырезал из неё
дверь, окно, коридор. Фигуры блокаута, `push_face`, `array` и Poly Shape у
нас были, вычитания не было.

## Что берём

1. **Браш — выпуклая фигура, операции по порядку** (Hammer, TrenchBroom,
   CSG-узлы Godot). Коробка, клин (как `builtin:ramp`), цилиндр N-гранником,
   лестница (коробка на ступень). Каждый браш либо добавляется, либо
   вырезает себя из всего, что добавлено до него; браш, добавленный после
   выреза, заполняет его снова — порядок важен, как в Godot.
2. **Carve из Hammer.** Серые коробки уже стоят в сцене: выделил стену,
   потом коробку-проём — Entity › Carve Selected, и проём вырезан.
   Разрезающие фигуры уходят из сцены, стена становится брашевым телом на
   своём месте, с тем же `id`, именем, материалом и местом.
3. **Сетка в метрах по мировым осям.** Текстурные координаты — метры по
   оси, куда грань смотрит больше всего; материал `grid` и любая
   текстура ложатся одинаково на всех гранях.

## Чего не берём и почему

* **Браш-меш в сцене (ProBuilder, CSG-узлы Godot).** Меш в сцене — сотни
  чисел в диффе. У нас, как у Poly Shape и террейна, браши — исходник
  ассета, а сцена ставит модель.
* **Браши как строки сцены** («этот ребёнок вычитается из родителя», как
  CSG-дети в Godot). Удобно, но это вторая правда о форме: геометрия,
  которая растёт при раскрытии сцены, должна попасть в физику, навигацию,
  миниатюры и выбор мышью. Сделать можно позже тем же ядром
  (`scrap::solid`), если окажется, что Carve мало: стена со строками-
  проёмами, как `along` у сплайна. Сейчас — нет.
* **Произвольные булевы операции над мешами** (Blender Boolean, Modeling
  Mode Unreal). Для блокаута хватает выпуклых брашей, а их вычитание
  простое и надёжное. Вычитать импортированную модель нельзя.
* **Ручки граней браша в окне.** Это будет инструмент вьюпорта вместе с
  ручкой `push_face`; пока браш правится строкой, Carve'ом или агентом.

## Как устроено

Исходник `assets/<имя>.scrbrush` — строка на браш:

```
(
    brushes: [
        (shape: Box, position: (0.0, 1.5, 0.0), scale: (8.0, 3.0, 0.25)),
        (op: Subtract, shape: Box, position: (-2.0, 1.0, 0.0), scale: (1.0, 2.0, 1.0)),
    ],
)
```

Поля — как у трансформа сущности (`position`, `rotation_deg`, `scale`),
фигура — единичная и по центру, как `builtin:`. Импорт держит тело
набором выпуклых кусков, которые не перекрываются: вычитание выпуклого
браша из выпуклого куска — не больше одного куска на плоскость браша
(Hammer делает так же). Потом грани, которыми куски прижаты друг к другу,
выбрасываются: рисуется и сталкивается только внешняя поверхность. Ядро —
`scrap::solid` в модуле геометрии: выпуклое тело, `clip`, `subtract`,
`add`, `boundary`. Разрушение режет им же — `Solid` переехал туда из
`scrap-destruction`, чтобы блокаут не зависел от разрушения.

Меш ставится как любая модель, `collider: Model, body: Static`: выбор
мышью, границы, миниатюры и навигация работают без изменений.

## Ответы постулатам

1. **Скорость итерации.** Браш — ассет: поправил строку и сохранил —
   работающая игра видит новую стену, как при правке `.scrpoly`. Сборка —
   миллисекунды на десятки брашей.
2. **Git.** Один браш — одна строка: дифф говорит «вырезали окно здесь».
   `brush_add` и Carve дописывают строку, не трогая остального текста и
   комментариев. Двое, добавившие по брашу в разные места списка,
   сливаются построчно; в конец одного файла — обычный конфликт текста.
   Порядок строк — смысл (вычитание режет то, что выше), поэтому
   мёрдж-драйвер для `.scrbrush` не нужен и не делается.
3. **Модульность.** Ядро — в модуле геометрии, импорт — в `scrap-import`
   (в игру не линкуется), Carve — действие реестра с модулем `blockout`.
   Игра без брашей не платит ничего: это обычный меш.
4. **Сеть.** Не касается: браш — форма статики, известная всем из ассета.
5. **AI.** Всё — функции сессии и MCP: `brush_shape`, `brush_add`,
   `brush_subtract`, `set_brushes`, `carve` (из реестра — тот же вызов,
   что меню). Ошибки — словами: «the brushes leave nothing», «brush 1: its
   scale…», «`ball` cuts only as a builtin cube, ramp, cylinder or
   stairs». Проверяется без дисплея: объём, площадь и «падает ли ящик в
   колодец».
6. **Производительность.** Стоимость — при импорте, в кадре — обычный
   меш. Куски режутся попарно: квадратично по числу брашей, для блокаута
   (десятки) — миллисекунды. Уровень из тысяч брашей в одном файле так не
   собрать; это сигнал делить его на несколько тел.
7. **Opinionated.** Одна операция по умолчанию — порядок строк; нет
   пересечения (intersect) и отдельных режимов — их никто не просил.
8. **Батарейки.** Человек без программиста режет проём мышью: две
   коробки, Carve Selected.

Открытых вопросов DNA карточка не касается.

## Чего пока нет

* Т-соединения: большая грань встречает несколько маленьких без общих
  вершин. Для блокаута незаметно, для запекания света может дать щели.
* Соседние куски одной плоскости не сливаются в одну грань — лишние
  треугольники, не больше.
* Браш нельзя вырезать импортированной моделью или Poly Shape; Carve
  принимает только `builtin:` куб, клин, цилиндр и лестницу.
* Правка файла — не шаг отмены сцены (как у `set_poly` и мазков
  террейна); история файла — в git.
