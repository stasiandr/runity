# runity-ui: свой UI для игр и редактора

Карточка к решению «UI — свой» (DNA, «Принятые решения», 2026-09-23). Она
отменяет решение «UI редактора — GPUI» и закрывает открытый вопрос 1.

## Почему не GPUI

Первое окно редактора на GPUI (коммиты `d002285`…`ffb0ad1`) работало, но
каждый шаг был компромиссом:

* **Кадр движка идёт через CPU.** У GPUI свой Metal-рендер, общего
  `wgpu`-устройства с движком нет. Кадр читается с GPU, байты
  переставляются RGBA→BGRA, картинка снова грузится в атлас GPUI. На
  2 Мп выходило ~9 кадров в секунду. Путь без копии (IOSurface) не
  проверен, и он только для macOS. На Windows нужен свой D3D-хэндл, на
  Linux — третий путь.
* **Окно только на macOS**, хотя постулат 7 требует один редактор на всех
  ПК.
* **Сборка.** Шейдеры GPUI компилируются при старте (`runtime_shaders`),
  потому что Xcode 26 вынес компилятор Metal в отдельный компонент на
  гигабайты. Дерево зависимостей — самое тяжёлое в workspace. Крейт —
  еженедельный снапшот от одного мейнтейнера.
* **Горячей перезагрузки UI нет** (постулат 1).
* **Игре он не подходит.** UI игры и UI редактора были бы двумя
  разными системами.

## Что делаем

Крейт `runity-ui`: retained-дерево узлов, раскладка на `taffy`, текст на
`glyphon`/`cosmic-text` (они уже есть в движке), рисование — наш `wgpu`
на том же устройстве, что и сцена. **Одна модель для игры и для
редактора.** Редактор — первый потребитель, инвентарь и меню игры —
следующие.

### Модель

* **Дерево узлов живёт между кадрами.** Узел — стиль (раскладка taffy
  плюс вид: фон, рамка, радиус, градиент, текст), содержимое (ничего,
  текст, иконка, картинка, текстура вьюпорта) и дети. Адрес узла —
  `NodeId` с поколением: удалённый узел не спутать с новым.
* **Изменения помечают грязным только то, что задели.** Поменялся текст —
  переформатируется одна строка. Поменялся размер — раскладка
  пересчитывается от этого узла. Поменялся только цвет — обновляется одна
  вершина. Кадр, в котором ничего не менялось, не стоит ничего: буфер
  вершин с прошлого кадра рисуется как есть. В этом разница с immediate
  mode, где каждый кадр описывается заново.
* **События — данные, а не замыкания.** Ввод (мышь, клавиши, текст, IME)
  проходит по дереву: hit-test, фокус, всплытие. На выходе —
  `ui.events()`: список `(NodeId, Event)`, где `Event` — `Click`,
  `Changed(text)`, `Submit`, `DragStart` и т. д. Игра читает их системой,
  редактор — функцией панели. Владение простое, и тест проверяет список, а
  не пытается вызвать замыкание.
* **Список из данных — ключевая сверка.** `ui.sync_children(parent, keys,
  build, update)` оставляет узлы тех ключей, что остались, создаёт новые и
  удаляет ушедшие. Hierarchy из 3000 строк — это сверка по `EntityId`, а
  не пересборка списка.
* **Виджеты с поведением — в ядре:** поле ввода (выделение, буфер обмена,
  IME через `cosmic_text::Editor`), прокрутка, виртуальный список,
  разделитель панелей, перетаскивание. Кнопка, тег или сегмент — просто
  функция, которая собирает поддерево из стилей темы.
* **Вьюпорт — узел, чьё содержимое — `wgpu`-текстура движка.** Без копии и
  без платформенных хэндлов на любой ОС.
* **Тема — данные.** Токены Nocturne (цвета, шаги отступов, радиусы,
  шрифт) лежат в RON-файле и перечитываются на ходу. Тема игры —
  отдельный файл того же формата.

### Рисование

Один конвейер на прямоугольники: SDF скруглённого прямоугольника с рамкой,
градиентом и мягкой тенью в фрагментном шейдере. Второй конвейер — на
текстурированные квады: глифы (атлас glyphon), иконки (SVG, растеризованные
в атлас), картинки и текстура вьюпорта. Порядок рисования — порядок
дерева, с клипом по прямоугольнику у прокрутки. Иконки — Lucide (ISC), SVG
в крейте: они уже были под рукой. Nocturne называет Phosphor (MIT); сетка
и штрих те же, замена набора — замена файлов.

## Ответы постулатам

1. **Скорость итерации.** Тема и стили перечитываются на ходу. Код
   панелей патчится через `subsecond`, а при патче панель пересобирает
   своё поддерево: дерево остаётся, фокус и прокрутка переживают правку.
   Крейт маленький и без тяжёлых generic'ов в API, поэтому игра, которая
   его подключает, не пересобирает лишнего.
2. **Git.** Раскладка — код, тема — текст (RON), дифф читается.
3. **Модульность.** `runity-ui` — отдельный крейт. Игра без UI его не
   подключает. Панель редактора — функция, которая строит поддерево в
   слоте дока, так что модуль приносит панель обычным Rust-кодом. Это и
   было обещание GPUI, но теперь без чужого рантайма.
4. **Сеть.** Не касается.
5. **AI.** UI рисуется headless через программный Vulkan, как golden-кадры
   движка. `ui.dump()` отдаёт дерево текстом: роли, тексты, прямоугольники.
   Агент кликает по имени узла, а не по пикселю. Окно редактора
   тестируется в CI на трёх ОС.
6. **Производительность.** Бюджеты тестами: пустой кадр без изменений —
   ноль перестроений; раскладка 10 000 узлов; сверка 3000 строк Hierarchy
   при смене одной; кадр UI ≤ 1 мс на редакторе. Масштаб — кривой
   10/100/1000/10 000.
7. **Opinionated.** Один UI на игру и редактор, одна тема по умолчанию на
   каждый. «Одна правда на подсистему»: слой `runity::ui` (квады плюс
   текст) и `runity::widgets` уходят. Дата удаления — когда диалоги и
   виджеты игры переедут на `runity-ui`, не позже конца 2026-10.
8. **Батарейки.** Инвентарь, меню, диалоги игры строятся тем же, чем
   редактор.

## Что принимаем как риск

* Текстовый ввод и IME — самая трудная часть, и её пишем мы (на
  `cosmic-text`).
* Доступности (screen reader) нет, и в ближайшее время не будет.
* Докинг, меню, контекстные меню, подсказки — всё своё, и это время.
* Окно одно. Несколько окон (вынести панель на второй монитор) winit
  позволяет, но в первые этапы не входит.

## Этапы

Сделано (2026-09-23): этапы 1–3. Прокрутку, клип, слои, поле ввода
(каретка, выделение, буфер обмена), иконки, подсказки в полях и сверку
списков по ключу несёт ядро; виртуального списка не понадобилось —
отрисовка отсекает поддеревья вне клипа, и 2000 строк Hierarchy стоят
строк на экране. Докинг — три дока со вкладками, панель переносится перетаскиванием вкладки. IME (предредактирование) и тема из RON — ещё нет.
Осталось: этап 4.

1. **Ядро.** Дерево, стили, taffy, SDF-прямоугольники, текст, hit-test и
   события, `dump()`. Headless-тест: дерево → PNG и дерево → текст.
2. **Виджеты.** Кнопка, иконка, тег, сегменты, поле ввода с IME,
   прокрутка, виртуальный список, разделитель. Тема Nocturne из RON.
3. **Редактор.** Окно на winit (`desktop-shell`), вьюпорт-узел с текстурой
   сессии без копии, тулбар, Hierarchy, Inspector, Console. Панели те же,
   что были на GPUI. После этого крейт GPUI удаляется.
4. **Игра.** Диалоги и виджеты игры переезжают на `runity-ui`, `runity::ui`
   и `runity::widgets` удаляются.
