## Что сейчас

`runity` — один крейт на сто тысяч строк. Сцена знает физику, свет, звук,
частицы и декали как свои типы: строка сцены (`EntityDesc`) — это поля всех
подсистем разом. Мир (`world.rs`) порождает всё сам. Выключить можно только
физику, звук, Steam и окно — cargo-фичами. Голого ядра нет.

## Модель

### Поле строки сцены принадлежит модулю

Строка сцены остаётся той же на диске: `body: Static`, `light: (…)`,
`sound: (…)` — как сейчас, файлы не переписываются. Меняется то, кто знает
тип поля. Ядро знает только своё: `id`, `name`, `prefab`, `transform`,
`inactive`, `in_part`, `components`, `overrides`, `children` (и прочее,
без чего нет префаба). Всё остальное — **части** (`parts`): текст значения,
как он написан, по имени поля — так же, как уже хранятся компоненты игры.

Тип части объявляет модуль: `impl Part for Light { const NAME = "light" }`.
Читается она по типу — `desc.part::<Light>()`, пишется — `set_part`. Ядро
не разбирает части при загрузке: проверяет, что это RON, и держит текст.
Ошибку значения называет тот, кто его читает, — спавн мира и `check`, с
файлом и сущностью, — как сегодня с компонентами игры.

Отсюда само собой выходит «компонент отключённого модуля не теряется»:
сцена с `body: Dynamic` открывается сборкой без физики, поле лежит текстом,
сохраняется байт в байт, а `check` говорит, что `body` не знает ни один
модуль этой сборки.

### Модуль — крейт

Модуль — крейт в `crates/`, со своим `module.ron` (манифест) рядом с
`Cargo.toml`. Ядро — `runity-core`. Крейт `runity` — фасад: подключает
модули по cargo-фичам и отдаёт их под привычными путями
(`runity::render::…`), так что игра и редактор пишут как раньше. Выключить
модуль — одна строка в `runity.ron` проекта, а фича фасада и зависимость
`Cargo.toml` игры выводятся из неё (`runity check` ловит расхождение).

Порядок разреза — от листьев графа зависимостей к ядру; каждый шаг
оставляет все тесты зелёными:

1. Части строки сцены (выше) — без этого ядро не отрезать.
2. Мир: ядро спавнит сущность (трансформ, иерархия, `SceneId`,
   компоненты игры), а модуль вешает своё по частям — через `Spawner`,
   которые собирает набор модулей (`Modules`).
3. `runity-core` — выносится из `runity`, `runity` становится фасадом.
4. Модули-крейты: `physics`, `geometry`, `gpu`, `render`, `ui`, `audio`,
   `net`, `animation`, `navigation`, `terrain` и остальные.

### Манифест

```ron
// crates/runity-physics/module.ron
(
    name: "physics",
    version: "0.1.0",
    engine: "0.1",          // с какими версиями ядра совместим
    depends: ["geometry"],
    runtime: true,          // приносит код в игру
    editor: false,          // приносит расширения редактора
    parts: ["body", "collider", "physics", "joint", "joint_break", "layer"],
    assets: [],             // модуль без кода — только это поле
)
```

Официальные модули — одной версией с ядром (поезд). Модуль без кода —
манифест и `assets/`.

### Фазы

Цикл — как PlayerLoop в Unity: `Initialization`, `EarlyUpdate`,
`FixedUpdate` (сегодняшний `step`), `Update`, `LateUpdate`,
`PostLateUpdate` (рендер, сегодняшний `frame`). Модуль вставляет свои
системы в фазу; игра — свои, в том же порядке, что пишет в `step`.

### Ввод

Ядро знает события устройств (`InputEvent`, состояние клавиш и мыши).
Действия, карты, привязки и схемы управления — модуль `input` (сегодняшние
`actions` и `input.ron` — его частный случай).

## Ответы постулатам

1. **Итерация.** Выключенный модуль не компилируется. Правка игры не
   пересобирает движок, как и раньше; фасад — тонкий. Части читаются из
   текста — перезагрузка сцены не меняется.
2. **Git.** Файлы сцен не меняются вовсе. Поле отключённого модуля
   переживает сохранение байт в байт.
3. **Модульность.** Это она.
4. **Сеть.** Сеть — модуль; сетевые компоненты регистрируются как
   раньше. Четыре друга видят то же.
5. **AI.** Каждый модуль тестируется отдельно, headless; `check` называет
   поле без модуля словами.
6. **Производительность.** Часть разбирается при спавне — это цена
   текста; кривые спавна 10…10 000 держат её тестом.
7. **Opinionated.** Одна реализация модуля по умолчанию, замена — крейтом
   с тем же швом.
8. **Батарейки.** `runity new` даёт голый, базовый или полный набор, или
   темплейт.
