# Экраны игры на HTML и CSS

Карточка к решению «Экраны игры — HTML и CSS» (DNA, «Принятые решения»,
2026-10-14). Стоит на [ui.md](ui.md): рисует тот же `scrap-ui`, это новый
формат экрана, а не новый UI.

## Зачем

Сегодняшний экран — `.screen.ron`: элементы на якорях, размеры в пикселях
кадра 1280×720 (`scrap::screen`). Он работает, но:

* **Вёрстки нет.** Каждый элемент стоит руками: `at: (-24, 54)`. Список
  заказов в kitchen рисует код, потому что повторить кусок экрана файл не
  умеет.
* **Формат знаем только мы.** HTML и CSS знает каждый — человек из веба,
  дизайнер, а лучше всех агент (постулат 5): модель пишет их увереннее
  любого своего формата.
* **В `git diff` читается плохо.** Смещения и размеры, которые ничего не
  говорят о намерении (постулат 2).

Как это решают другие: Coherent Gameface (UI в играх на HTML/CSS/JS, свой
рендерер на устройстве игры вместо Chromium), NoesisGUI (XAML), Unity UI
Toolkit (UXML и USS — та же идея своим синтаксисом). Мы берём подход
Gameface — подмножество HTML и CSS, свой рендер, данные из модели игры
через `data-bind-*` — но **без JavaScript**.

## Что делаем

Модуль `scrap_ui::markup`. Экран — файл `.screen.html` и стили `.css`,
которые он подключает:

```html
<link rel="stylesheet" href="hud.css">

<header class="top">
  <span id="clock">{{round.clock}}</span>
  <span class="score">Score {{round.score}}</span>
</header>
<div class="health">
  <div class="fill" data-bind-style-width="{{player.hp / player.max * 100}}%"></div>
</div>
<div id="orders" class="orders">
  <div class="order" data-bind-for="order:{{orders}}" data-bind-class-toggle="late:{{order.left < 10}}">
    <span>{{order.dish}}</span>
    <button id="cancel">@hud.cancel</button>
  </div>
</div>
<button id="leave" data-bind-if="{{round.over}}">@hud.leave</button>
```

```rust
use scrap::html::Screen;

// При загрузке: дерево UI, шрифт игры, экран в нём.
let mut ui = scrap::scrap_ui::Ui::new();
ui.add_font(FONT.to_vec());                 // font-family: "Kenney Future"
let mut hud = Screen::load(path)?;         // Problems: файл:строка:столбец
hud.mount(&mut ui, ui.root());

// Каждый кадр, в Game::frame: оболочка уже отдала дереву указатель.
let done = hud.read(&ui.events());
if done.clicked("leave") { … }
if let Some(row) = done.clicked_row("cancel") { orders.remove(row); }
hud.set("round", &round);                   // всё, что Serialize
hud.set("orders", &orders);
hud.set_strings(&strings);                  // @ключи; тот же язык — ничего
hud.update(&mut ui);                        // без изменений — ничего

// И отдать дерево оболочке: она его рисует поверх кадра.
impl scrap::shell::Game for Game {
    fn ui(&mut self) -> Option<&mut scrap::scrap_ui::Ui> { Some(&mut self.ui) }
}
```

* **Оболочка рисует дерево игры** (`Game::ui`): поверх сцены и оверлея,
  в окне, в Game view редактора и в браузере. Перед `Game::frame` она
  подгоняет дерево под окно, как Canvas Scaler Unity
  (`scrap::html::fit`: экран свёрстан для 1280×720 и масштабируется по
  высоте, у окна уже 16:9 — по ширине), и отдаёт ему указатель, клавиши,
  палец и сценарий ввода (`SCRAP_INPUT_SCRIPT`) в его пикселях. С потоком
  рендера: дерево готовится (`UiRenderer::prepare`) на потоке игры, где
  оно живёт, а рисуется там, где кадр.

* **HTML и CSS превращаются в дерево `scrap-ui`.** Раскладка — `taffy`, а
  это и есть flexbox CSS. Рисует рендерер движка на его устройстве, как
  редактор. Браузера нет.
* **Модель — от игры, привязки — в разметке**, как в Gameface:
  `{{ }}` в тексте и `data-bind-value`, `data-bind-if`, `data-bind-for`
  (`item:{{list}}`, `i, item:{{list}}`), `data-bind-class-toggle`
  (`class:{{условие}}`), `data-bind-style-<свойство>`. `Screen::set` берёт
  любой `Serialize`: модель — это `serde_json::Value`.
* **Изменилась модель — меняется только то, что от неё зависит.** Дерево
  узлов живёт между кадрами; `set_style` и `set_text` с тем же значением
  ничего не стоят. Строки `data-bind-for` сверяются по месту: те, что были,
  остаются теми же узлами, лишние удаляются, новые встают на своё место.
* **Что сделал игрок — данные по `id`.** `Screen::read` переводит
  `ui.events()` в `Done`: клик, текст поля, Enter — с `id` ближайшего
  элемента, у которого он есть, и номером строки списка. Несколько экранов
  читают один список событий.
* **`@ключ` — перевод** из `content/localization/` (`set_strings`), как
  в `.screen.ron`; `Screen::keys` отдаёт ключи `scrap check`.
* **Файлы перечитываются на ходу** (`Screen::poll`): дерево строится
  заново из той же модели; файл с ошибкой — список ошибок, и остаётся
  последний рабочий экран.

### Что читается

**HTML.** `div`, `section`, `header`, `footer`, `main`, `nav`, `aside`,
`article`, `ul`, `ol`, `li`, `span`, `p`, `label`, `strong`, `b`, `small`,
`h1`–`h4`, `button`, `input` (текстовое поле, `placeholder`, `value`).
`<html>`, `<head>`, `<body>` можно не писать. В `<head>` — `<link
rel="stylesheet">`, `<style>`, `<title>`, `<meta>`. Атрибуты: `id`,
`class`, `style` и привязки.

**CSS.** Селекторы: тег, `.класс`, `#id`, `*`, их сочетания, потомок
(пробел) и ребёнок (`>`), `:hover` и `:active` в конце. Каскад — как в
CSS: специфичность, потом порядок; текстовые свойства наследуются.
Переменные — `--имя` в `:root` и `var(--имя, запасное)`. Свойства:
раскладка flexbox (`display: flex|none`, `flex-*`, `justify-content`,
`align-*`, `gap`), размеры (`width`…`max-height`, `aspect-ratio`),
`padding`, `margin`, `position: absolute` с `top/right/bottom/left/inset`,
`overflow`; вид — `background` цветом, `border` сплошной одной ширины,
`border-radius` одним радиусом, `opacity`, `cursor: pointer`,
`pointer-events: none`; текст — `color`, `font-size`, `font-weight`,
`font-family: sans-serif|monospace`, `line-height`, `text-align`,
`white-space`. Единицы — `px`, `%`, `vw`, `vh`, `rem` (16px). Цвета —
`#rgb`, `#rrggbb(aa)`, `rgb()`, `rgba()` и основные имена.

**Выражения в `{{ }}`.** Путь в модели (`player.hp`, `orders.length`,
`orders.0.dish`), числа, строки, `true/false/null`, `+ - * / %`,
сравнения, `&& || !`, скобки. Ни вызовов, ни присваиваний, ни `? :`.

### Чем это не браузер — и это сказано громко

* **Всё, чего UI не нарисует, — ошибка со строкой и столбцом, а не тихо
  пропущенное правило.** Браузер прощает незакрытый `<div>` и неизвестное
  свойство; агенту, который это написал, нужно об этом услышать
  (постулат 5). Так говорят и `Screen::load`, и `scrap check`:
  `hud.css:3:3: \`float\` is not a property this UI reads`.
* **Каждый элемент — уже flex-колонка**, как в Gameface и React Native;
  «строчные» теги (`span`, `p`, `button`…) — ряд. Блочной и строчной
  вёрстки нет: текст `Score: <b>5</b>` — два элемента в ряд, не одна
  строка с жирным словом. Слова элемента — в своём узле внутри него, как
  анонимный блок CSS: `align-items` и `justify-content` элемента ставят
  их, `text-align` выравнивает строки (`Screen::text` читает их по `id`).
* **Шрифты** — Inter по умолчанию, `monospace`, или шрифт, который игра
  добавила (`Ui::add_font`), по имени семейства. Семейство, которого в
  дереве нет, `Screen::missing()` называет (`font \`X\``).
* **`:hover` и `:active` меняют только вид** (фон, цвет рамки): так
  устроен `scrap-ui`, состояние под указателем не перекладывает дерево.
* **Нет пока:** картинок (`<img>` ждёт ссылок на ассеты, см. ниже), сетки
  (`display: grid`), анимаций и переходов (`transition`, `@keyframes`),
  `@media`, рамки по сторонам, градиентов, `z-index`.
  Каждое — понятная ошибка с подсказкой, что писать вместо.

## Ответы постулатам

1. **Скорость итерации.** Сохранил `.css` или `.screen.html` — экран в
   работающей игре перестроен из той же модели, состояние игры не
   трогается. Сломанный файл — ошибки со строкой, и остаётся последний
   рабочий (тест). Логика экрана — Rust игры, и она патчится `subsecond`,
   как вся игра. Сборку не удлиняет: разбор свой, без браузерного движка;
   новые зависимости `scrap-ui` — `serde` и `serde_json`, они уже в
   дереве.
2. **Git.** Экран — текст, который читается в `git diff` лучше
   `.screen.ron`: `width: 240px` в классе вместо смещений у каждого
   элемента. Два человека, поменявшие разные правила одного `.css`,
   сливаются git'ом построчно; одно правило — обычный конфликт текста.
   **Нарушение постулата 2, явно:** `<link href="hud.css">` — путь, а не
   ссылка по ID. Так пишет весь веб, и экран со своим `.css` лежат рядом;
   переименованный мимо движка `.css` рвёт ссылку, а `scrap check` её
   называет (`the stylesheet ... cannot be read`). Чинить — открытый
   вопрос 1 ниже.
3. **Модульность.** Это модуль `markup` в `scrap-ui`; игра без UI его не
   тянет. Логика — данные и события, так что заменить формат можно, не
   трогая игру: модель и `Done` останутся. Полный браузер с JS кто-то
   может принести своим модулем на тот же шов — официального не будет.
4. **Сеть.** Не касается: экран показывает модель своего участника. Что
   видят четверо друзей, решают компоненты, которые игра кладёт в модель.
5. **AI.** Самый сильный ответ: HTML и CSS агент пишет без обучения. Всё
   headless: `ui.dump()` даёт дерево текстом, `Screen::node(id)` и
   `ui.click` — нажать по имени, golden-кадр на lavapipe (тест
   `an_html_screen_draws_as_its_css_says`). Ошибки — с файлом, строкой и
   тем, что писать вместо; `Screen::missing()` называет пути, которых нет
   в модели (опечатка `player.nmae`). **JS нет сознательно:** логика —
   Rust (постулат 5); `<script>` и `onclick` — ошибка с объяснением.
   **На границе постулата:** выражения в `{{ }}` — крошечный язык. Как и
   провода (docs/wires.md), он только читает: без вызовов, присваиваний и
   условий-веток. Просьба «добавить функцию в выражение» — вопрос к ДНК,
   а не новая фича; ответ по умолчанию — ещё одно поле в модели.
6. **Производительность.** Кадр без изменений стоит ничего: `update`
   выходит сразу, если модель и окно те же (тест: ревизия рисования не
   меняется). При изменении модели — проход по экрану с подбором
   селекторов, но перестраивается только то, что поменялось. Бюджет с
   кривой 10/100/1000 элементов — этап 2 ниже, пока не держится тестом.
7. **Opinionated.** Одно умолчание: flex-колонка, Inter, тема из UA-листа
   (`markup/ua.css`). **Нарушение «одной правды на подсистему», явно:**
   два формата экрана — `.screen.ron` и `.screen.html`. `.screen.ron`
   уходит вместе со слоем `scrap-overlay` (этап 4 ui.md): когда экраны
   kitchen переедут, не позже 2026-12-31.
8. **Батарейки.** Экраны в HTML пишет человек без программиста; не
   хватает пока окна в редакторе (UI Builder сегодня правит `.screen.ron`)
   и картинок — этапы ниже.

## Веб: DOM вместо рисования

На вебе игра — wasm, рисующий в `<canvas>`. Экран можно было бы собирать
настоящими элементами DOM поверх холста. **Решение:** не по умолчанию.

* По умолчанию и на вебе экран рисует `scrap-ui` через WebGPU — один
  рендер на все платформы (постулат 7).
* Подмножество HTML/CSS — закон на любой платформе: тот же разбор и те
  же ошибки, так что браузер не примет больше, чем десктоп.
* Позже — DOM как дополнительный бэкенд, начиная с того, что браузер
  делает лучше: текстовые поля и диалоги на телефоне (экранная
  клавиатура, IME, автозаполнение, доступность). До доверия к нему — тест
  совпадения: каждый экран примеров рисуется обоими путями (wgpu headless
  и DOM в Playwright), картинки сравниваются. Экраны в мире, под
  постобработкой и в кадрах для агента (`render`) остаются на wgpu.

## Открытые вопросы

1. **Ссылки на стили и картинки.** `href` — путь (нарушение постулата 2
   выше). Варианты: путь плюс подсказка по ID в сайдкаре, как у ассетов
   (`docs/refs.md`), или `href` по имени файла с поиском по индексу
   проекта. Картинки (`<img>`) ждут того же решения.
2. **Компоненты экрана.** Кусок экрана, который ставится в другие, как
   префаб в сцену (NEXT_STEPS, «Компоненты экрана»): `<template>` с
   именем или отдельный файл. Сейчас повтор — только `data-bind-for`.

## Этапы

Сделано (2026-10-14):

* `scrap_ui::markup`: разбор HTML (`html.rs`) и CSS (`css.rs`) с ошибками
  в строке и столбце, каскад и наследование, переменные, `:hover` и
  `:active`; выражения `{{ }}` (`expr.rs`); `Screen` — сборка дерева,
  привязки, списки со сверкой по месту, события по `id` и строке,
  перечитывание файлов, `@ключи`, `missing()`.
* В `scrap-ui`: `text-align` (`TextStyle::align`), `Ui::add_at`,
  `Ui::place_at`.
* Виды файлов `.screen.html` и `.css` в индексе проекта: `scrap build`
  везёт их в `data/`, `scrap check` читает каждый экран так же, как игра,
  и называет ошибки и ключи переводов.
* Тесты: 21 в модуле, golden-кадр примера HUD
  (`crates/scrap-ui/tests/screens/`) на lavapipe, `scrap check` над
  проектом с ошибками в `.screen.html` и `.css`.

Сделано (2026-10-15):

* **Игра рисует `scrap-ui`.** `Game::ui` отдаёт оболочке дерево; она
  подгоняет его под окно (`scrap::html::fit`), отдаёт ввод
  (`scrap::html::pointer`: позиции в пиксели CSS, палец — мышь) и рисует
  поверх оверлея (`UiRenderer::draw_prepared`) — в окне с потоком рендера
  и без, в Game view редактора (`embedded.rs`) и в браузере.
  `InputScript::due` отдаёт сценарий ввода и дереву, так что игра,
  сыгранная сценарием, нажимает кнопки HTML тем же путём, что и мышь.
* Шрифты игры (`Ui::add_font`, `font-family`), слова элемента в своём
  узле, `scrap::html` и `scrap::scrap_ui` в фасаде; `scrap-ui` берёт
  `Instant` из `web_time`, чтобы двойной клик работал в браузере.
* **HUD kitchen — на HTML** (`ui/screens/hud.screen.html` и `hud.css`):
  часы, счёт, кто в игре, слово шефа, клавиши, кнопка «Leave» и карточки
  заказов — `data-bind-for` с полосой терпения
  (`data-bind-style-width`), краснеющей на последней четверти
  (`data-bind-class-toggle`), вместо карточек, которые рисовал код. Сайдкар
  переехал с прежнего `hud.screen.ron`, ID тот же; `.screen.html` получает
  сайдкар с ID, как `.screen.ron`. Проверено: тест kitchen нажимает «Leave»
  через дерево и получает `Wish::Leave`; снимок раунда
  (`target/shots/round.png`); и сама игра в окне (Xvfb, lavapipe) по
  сценарию ввода — меню, Host, кухня с HUD, указатель над «Leave» даёт
  цвет `:hover` (`#f5873a`), клик возвращает в меню.

Осталось:

1. **Бюджет:** `update` после смены одного поля и полная сборка на
   10/100/1000 элементов — тестом с кривой (постулат 6).
2. **Остальные экраны kitchen** (меню, лобби, пауза, итоги, слово шефа,
   хозяин ушёл) — в `.screen.html`; им нужны ползунок, выбор из списка и
   список, которых в подмножестве пока нет. `kitchen-web` — следом;
   `scrap new` кладёт `hud.screen.html`. Потом `.screen.ron` и
   `scrap-overlay` удаляются.
3. **Android:** дерево рисуется в кадр, увиденный как простые байты
   (`AcquiredFrame::ui_view`); где Vulkan Android не умеет второго вида
   цепочки кадров, нужен запасной путь — до проверки на устройстве.
4. **Окно в редакторе:** вкладка Screens открывает `.screen.html` —
   текст рядом с картинкой, ошибки строкой Console.
5. **Картинки и компоненты** — после открытых вопросов 1 и 2.
6. **Движение:** `transition` для вида (цвет, прозрачность), потом
   размеров.
7. **DOM на вебе** — как в разделе выше.
