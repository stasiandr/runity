# Художнику — как в Unreal

Карточка к решению DNA «Пять вещей из Unreal для художников» (2026-09-23).

Unity хорош, но художнику удобнее Unreal: там результат доводят без
программиста — подкручивают вид, заселяют уровень, двигают физику и
забирают, что получилось. Из длинного списка того, чем Unreal удобен,
выбраны пять вещей: большая польза при небольшой цене и без конфликта с
постулатами. Берём мысль, а не реализацию.

## Что берём

1. **Забрать результат симуляции (Keep Simulation Changes, K).** Play в
   редакторе у нас — это уже Simulate из Unreal: физика идёт в мире
   редактора без кода игры (игра — отдельный процесс, Start Game). Правки
   во время Play отказываются, чтобы изменения не терялись молча, как в
   Unity. Не хватает обратного пути: ящики упали красиво — оставить их так.
   K во время Play помечает выделенное; Stop возвращает сцену и тем же
   действием кладёт помеченным их положение из симуляции — одним шагом
   отмены.
2. **Кисть растительности (Foliage).** Модель или префаб рисуются по
   поверхности кистью: радиус, плотность, случайный масштаб и поворот,
   выравнивание по нормали. Shift стирает. Каждое касание — копии в группе
   этой модели, как у `scatter`: сцена говорит, что где стоит, а не
   хранит «облако» отдельно.
3. **Сплайны и генераторы (Construction Script).** Сплайн — точки на
   сущности. Генератор — данные на сущности, из которых редактор строит
   дочерние сущности и перестраивает их при каждой правке: забор из модели
   вдоль сплайна с шагом, ряд. В файл пишутся параметры, а не то, что из них
   выросло, — дифф показывает «шаг 2 м → 1.5 м», а не сто строк столбиков.
4. **Инспектор как Details.** Жёлтая стрелка у поля, которое отличается от
   значения по умолчанию или от префаба, — сброс одним кликом. Поиск по
   полям. Сейчас сброс спрятан в контекстном меню подписи.
5. **Экземпляры материалов (Material Instances).** Материал-родитель и
   экземпляры, которые меняют только параметры (цвет, шероховатость,
   текстуру), видны сразу, без пересборки. Экземпляр ссылается на родителя
   ссылкой (docs/refs.md). Это делаем вместе с сессией рендера и
   материалов.

## Чего не берём и почему

* **Blueprints.** Код игры — Rust (постулат 7: одна правда). Визуальный
  скриптинг — второй язык с его отладкой и мёрджем.
* **One File Per Actor.** Мёрдж сцен уже решён драйвером по ID сущностей
  (постулат 2).
* **Режимы вьюпорта (Unlit, Wireframe, Lighting Only)** — полезны, но это
  проходы рендера: их делает сессия рендера (решение «Рендер-путь из
  отключаемых проходов»).

## Ответы постулатам

1. **Скорость итерации.** K убирает цикл «запомнил, где упало, остановил,
   расставил руками». Генератор перестраивается на каждую правку поля.
   Экземпляр материала меняется без пересборки.
2. **Git.** Результат K — обычная правка трансформов, видна в диффе. Кисть
   пишет строки сущностей в группу, как `scatter`. Генератор пишет
   параметры, а не результат.
3. **Модульность.** Кисть, сплайны и генераторы — инструменты редактора,
   которые приносит модуль блокаута; генераторы игры — модуль игры.
4. **Сеть.** Не касается: всё это время правки, а не игры.
5. **AI.** Каждое — действие сессии и MCP-инструмент: агент «оставь как
   упало», «засади склон соснами», «забор вдоль этой линии».
6. **Производительность.** Кисть добавляет сущности: тысяча сосен — тысяча
   строк. Держим кривой 10/100/1000/10 000; инстансинг — забота рендера.
7. **Opinionated.** Одна кисть, один сплайн, один способ сбросить поле.
8. **Батарейки.** Всё пятеро — из коробки, без кода игры.

## Открытый вопрос

Генераторы игры. Встроенные генераторы (вдоль сплайна, ряд) живут в
движке. Генератор, который пишет игра, — это код игры, который должен
работать в редакторе, а редактор не линкует код игры (постулат 3, форма
компонентов из `library/components.ron`). Вариантов два: игра
перестраивает генераторы у себя и отдаёт результат через отчёт, как
состояние аниматора, или редактор подгружает модуль игры с генераторами.
Не решаем, пока не понадобится первый генератор игры.

## Этапы

1. Keep Simulation Changes (K).
2. Инспектор: стрелки сброса и поиск по полям.
3. Кисть растительности.
4. Сплайны и встроенные генераторы.
5. Экземпляры материалов — с сессией рендера.
