# Открытый вопрос 1: вьюпорт движка внутри GPUI — план прототипа

Записка к решению, а не решение. Всё, что редактор делает, уже есть без
окна (`runity-editor`: Scene view, иерархия, инспектор, консоль — данными и
функциями, с тестами); окну осталось показывать кадр и пересылать ввод
(`Session::scene_view(&Input, dt)`). Вопрос — как показать кадр движка в
GPUI без копирования.

## Что проверить на Mac

1. Движок рисует в `OffscreenTarget`, текстура которого создана поверх
   `IOSurface` (через `wgpu-hal` Metal: `MTLTexture` из `IOSurfaceRef`).
2. GPUI показывает ту же `IOSurface` элементом `surface()`.
3. Кадр меняется каждые 16 мс без `read_rgba` и без копии на CPU; ресайз
   пересоздаёт поверхность; двойная буферизация, чтобы GPUI не читал
   поверхность, в которую движок пишет.

Критерий: 60 кадров/с на Scene view с 3000 сущностями, без разрывов, на
M-серии; время кадра движка в `perf` не выросло.

## Запасной путь, если не выйдет

Копия через CPU (`read_rgba` → `ImageData` GPUI) — работает везде сразу,
стоит ~2–4 мс на кадр 1920×1080; годится для первых недель грейбокса, пока
идёт прототип. Windows позже — общий D3D-хэндл, та же схема.

Решение и прототип — на Mac; здесь (Linux-контейнер без экрана) их не
сделать.
