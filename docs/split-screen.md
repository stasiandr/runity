# Двое за одним экраном: сплит, свои геймпады, свой UI

Карточка к трём пробелам, в которые упёрлась первая кооперативная игра
на диване (Not Divinity, M0): один кадр — одна камера, все геймпады
сливались в один ввод, экран раскладывался на всё окно с одним фокусом.
Unity делает это камерами с Viewport Rect, `PlayerInput` по устройствам
(`PlayerInputManager`, Split-Screen) и `MultiplayerEventSystem` на
игрока. Берём то же, в форме движка.

## Что берём

1. **Виды кадра (Viewport Rect).** `Frame::views: Vec<FrameView>` —
   камера и её прямоугольник (`ViewRect::Share` в долях окна,
   `ViewRect::Pixels`; готовые `LEFT`, `RIGHT`, `TOP`, `BOTTOM`). Пусто —
   кадр как был: `camera` на всё окно. Не пусто — каждый вид рисуется
   целым конвейером (свет, тени, пост, частицы) в свою картинку размером
   с прямоугольник, с его аспектом, и кладётся на место; что не покрыто
   видами — чёрное. Один раз на кадр, а не на вид: картинки камер,
   пробы отражений, таблицы неба, живые меши, молния. Своё у каждого
   вида (`ViewState`): история TAA, глубина прошлого кадра для
   отсечения, каскады теней солнца, часы экспозиции, SSAO, облака,
   полуразмерные частицы, линза. Первый вид рисуется на собственном
   состоянии рендерера — игра с одним видом не отличается ничем. Тот же
   путь у окна и у `Renderer::render` в `OffscreenTarget` (тесты).
   Своё и в кадре: `FrameView::draws` — то, что рисуется только в этом
   виде, поверх общих `Frame::draws` (Culling Mask камеры Unity, сказанный
   с другой стороны). Стена, срезанная до пенька со стороны камеры одного
   игрока, пока другой видит её целой; метка над своим героем. Светится,
   отбрасывает тени и отсекается как общие, но только в проходе своего
   вида. `FrameView::new(camera, rect).with_draws(draws)`.
2. **Геймпад по устройству (PlayerInput).** Окно больше не выбрасывает
   id геймпада gilrs: `PadSlots` даёт каждому слот игрока по порядку
   подключения; ушедший держит слот пустым, вернувшийся (или следующий
   новый) занимает наименьший пустой. События `PadDownOn { pad, button }`,
   `PadUpOn`, `PadMovedOn { pad, axis, value }`, `PadConnected(slot)`,
   `PadDisconnected(slot)`; `Input::pad(slot) -> Option<&PadState>` —
   кнопки и стики одного слота. Сводный вид (`pad_held`, `pad_axis`)
   работает как раньше и видит все: кнопка отпущена, когда её не держит
   ни один, стик — самый отклонённый.
3. **Игрок на своих устройствах (Control Scheme на игрока).**
   `Seat { pads, keys, mouse }`: `Seat::pad(1).with_keyboard("arrows")`.
   В `input.ron` — `keyboards`: стороны одной клавиатуры, наборы
   привязок клавиш, которые считаются только для сидящего за этой
   стороной; клавиши вне сторон — для всех с клавиатурой.
   `actions.held_by / pressed_by / released_by / axis_by(&input, &seat,
   name)` — та же карта действий для игрока N. Старые `held` и прочие —
   это `Seat::everything()`, всё как было. `with_whole_keyboard()` —
   отладочное «вся клавиатура у этого игрока».
4. **Сценарий для второго геймпада.** `SCRAP_INPUT_SCRIPT` — те же
   события: `(1.0, PadDownOn(pad: 1, button: South))`,
   `(1.0, PadMovedOn(pad: 1, axis: LeftX, value: 1.0))`. Слот, о
   котором заговорили, появляется подключённым — двух геймпадов в руках
   для теста не нужно.
5. **Экран в области (Canvas на камеру).** `Region { rect, reference }`:
   `Screen::draw_region(widgets, ui, input, region, strings)` раскладывает
   файл экрана в прямоугольнике — якоря его углы и края, кадр 1280×720
   (или `with_reference(640.0, 720.0)`) вписан в него — и режет всё
   по нему (`Ui::push_clip`). Для кода: `region.place(anchor, at, size)`
   и `region.clip(&mut ui)`.
6. **Свой фокус у каждого (MultiplayerEventSystem).** Фокус — это
   `Widgets`; у игрока свой. `Widgets::begin_frame_with(Moves)`: шаг,
   стик, «принять», «назад» — из его геймпада (`Moves::from_pad`) или из
   его клавиш через его `Seat`. `set_mouse(false)` — мышь не его.

## Чего не берём и почему

* **Свой рендерер на вид.** Меши, текстуры и конвейеры загружены один
  раз; второй рендерер — вдвое памяти и разъехавшиеся хэндлы.
* **Пока общее на всех видах** (при сплите с ними неправильно): история
  апскейлера (MetalFX temporal, динамическое разрешение), резервуары
  ReSTIR, история объёмного тумана. Тени ламп рисуются заново на каждый
  вид, хотя от вида не зависят. Статистика кадра — последнего вида.
* **Окно Frame Debugger** записывает последний вид.

## Ответы постулатам

1. **Скорость итерации.** Сплит и привязки — данные кадра и `input.ron`,
   перечитываются на ходу; экран в области — тот же файл экрана.
2. **Git.** Стороны клавиатуры — строки `input.ron`; виды — код игры.
3. **Модульность.** Виды — рендер, слоты и `PadState` — ядро ввода,
   `Seat` — модуль `input`, области и фокусы — `overlay`. Игра с одним
   видом и одним игроком не платит ничем: пустой `views` — прежний путь.
4. **Сеть.** Локальные игроки — устройства одной машины; сетевая партия
   их не видит.
5. **AI.** Агент проверяет двух игроков сценарием ввода и снимком
   кадра без окна; тесты: `split_screen.rs` (две половины — две
   картинки, один вид на всё окно — прежний кадр), сценарий второго
   геймпада, два фокуса на двух меню.
6. **Производительность.** Второй вид — второй проход конвейера (так у
   всех), общее не повторяется; копия вида на место — один полноэкранный
   треугольник. Состояние вида создаётся один раз.
7. **Opinionated.** Слоты по порядку подключения; стороны клавиатуры —
   именованные наборы, а не переназначение клавиш.
8. **Батарейки.** Кооп на диване — три вызова: `views`, `Seat`,
   `draw_region`.
