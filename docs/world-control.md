# Мир идущей игры снаружи — world control

Живой MCP (docs/live-mcp.md) даёт агенту студию: сцену, Play, Game view.
Игра, запущенная в своём окне (`cargo run`, сборка у владельца), была для
агента чёрным ящиком: он не видел кадра окна, не мог нажать клавишу
игрока, спросить, сколько у героя здоровья, поставить игру на паузу и
сделать шаг. Автор попросил **универсальный** инструмент: любой игре на
scrap — запросы к её миру ECS (компоненты движка и **игры**), запись,
снимки и разницы, ожидания, время, кадр окна, ввод, плюс то, что игра
держит вне мира, и программы из этих команд.

## Что берём

1. **Сокет управления в оболочке** (`scrap::shell::control`). `SCRAP_CONTROL=1`
   (или путь; у игры — свой флаг, у Not Divinity `ND_DEBUG=1`) открывает
   Unix-сокет с правами 0600 и рядом `<сокет>.json` (0600): путь, случайный
   токен, pid, имя игры. Без флага сокета нет; в браузере и на телефоне
   его нет вовсе. Строка JSON — запрос `{"v":1,"token":…,"id":7,"cmd":…,"args":{…}}`,
   строка JSON — ответ ровно один раз: `{"v":1,"re":7,"ok":true,"seq":n,"frame":turn,"result":…}`
   или `"ok":false,"code":"unknown_command|unauthorized|bad_request|timeout|failed","error":"…"}`.
   Потоки соединений только читают и пишут; запрос исполняет цикл окна
   **в начале хода, до фиксированных шагов**: правка попадает в мир раньше
   систем, которые её прочтут на этом шаге, а чтение видит то, на чём
   остановился прошлый шаг. Команды игры спрашиваются после её `frame`
   (контекст с рендерером под рукой). Ответ «ещё нет» (`Answer::Pending`)
   — запрос спрашивают снова в следующем кадре, пока не ответит или не
   истечёт `timeout` (60 с): так ждут без опроса.
2. **Свои команды оболочки** — у любой игры без строчки её кода: `hello`,
   `shot` (кадр **ровно как его показало окно**, после оверлея: копия
   swapchain, PNG в файл — путь в ответе, без base64; половина экрана
   `half=p1|p2`, `crop`, `width`, `frames=N` подряд, `after=N`), `input`
   (события как от устройства, каждое в свой кадр: `["KeyDown(Space)",
   [6,"KeyUp(Space)"]]`), `pause` / `resume` / `step steps=N` / `frames
   frames=N` / `time_scale`, `perf` (последние кадры: fps, avg, p50, p99,
   худший, шагов на кадр, GPU), `script`, `quit`.
3. **Мир** (`scrap::world_control::WorldControl`) — одна строка в
   `Game::control` игры (kitchen: `self.world_control.answer(&mut
   self.world, &self.components, cmd, args)`). Сущность — номер
   (`hecs::Entity::to_bits`) или имя строки сцены. Компонент — имя, под
   которым его знают сцены (`hero`), части движка — `transform`, `name`,
   `parent`, `active`. Команды: `components` (все зарегистрированные:
   read-write или write-only, поля по `Shape`), `query` (`with=a,b`,
   `where="hero.hp < 10"`, `name`, `near=[x,y,z,r]`, `offset/limit`,
   `count`), `get` (вся сущность или компонент, `path=stats.hp`), `set`
   (целиком или поле по пути; значение проходит через тип компонента —
   неверное отвергается словами serde), `add` (значение или `()` —
   умолчания полей, как строка сцены), `remove`, `spawn`, `despawn`
   (с детьми), `revert n=…` (последние правки назад), `snapshot` / `diff`
   (сущности пришли/ушли, компоненты надеты/сняты, поля «было/стало»),
   `until where=…` (ответ, когда условие выполнилось).
4. **Компоненты игры — без клея.** `Components` хранит для каждого
   зарегистрированного типа `has`, а для тех, что выводят `Serialize`
   (их build.rs регистрирует `register_saved`, плюс новый
   `register_inspected` — читаемый, но не сохраняемый), чтение и запись
   как JSON. Остальные — write-only: надеваются из RON и снимаются, а
   `get` отвечает рецептом: «derive Serialize и зарегистрируй saved или
   inspected».
5. **Ресурсы и команды игры** (`world_control::Registry<G>`): то, что
   игра держит вне мира (у Not Divinity — забег nd-run, бой, свободный
   обход, камеры, настройки), регистрируется как именованные значения
   (`fn(&G) -> Value`, у записываемых ещё `fn(&mut G, Value)`) и команды
   (`fn(&mut G, &Value) -> Answer`). `res get|set NAME [path]`, `call NAME`
   или просто имя команды. `help` у игры собирает всё: оболочку, мир,
   ресурсы и команды — агент изучает незнакомую игру, не читая код.
6. **Программы** (`script`): Rhai на своём потоке. `cmd(name, #{…})`
   отправляет запрос в тот же стол, что клиент, и **блокируется** до
   ответа — ожидание в скрипте обычный вызов, игра идёт дальше. Пролог
   (`script::PRELUDE`) даёт имена командам (`query`, `count`, `first`,
   `get`, `set`, `patch`, `add`, `remove`, `spawn_entity`, `despawn`,
   `snapshot`, `diff`, `revert`, `pause`, `step`, `wait_frames`,
   `wait_until`, `shot`, `perf`, `input`, `res`, `res_set`, `game`,
   `press`, `hold`, `wait_for`), случаи `test(name, || …)` и проверки
   `assert_true/assert_eq/assert_lt`. Ответ: `{status ok|failed|error|cancelled,
   value, cases[{name, ok, error, ms}], failed, log, ms, line}` — ошибка
   со строкой скрипта. Один скрипт за раз (второй — `busy`),
   `script_cancel`.
7. **CLI**: `scrap world <команда> [ключ=значение …]` находит сокет сам
   (`--socket`, `SCRAP_CONTROL`, иначе самая новая живая карточка во
   временной папке), значение, читающееся как JSON, — JSON, иначе текст;
   голые слова — первые аргументы команды (`scrap world get 42 hero hp`).
   Печатает ответ одной строкой JSON; ошибка — код выхода 1.

## Почему Rhai

| | Rhai | Rune | Steel | своя мини-грамматика |
|---|---|---|---|---|
| ожидание кадров | поток скрипта блокирован на канале — естественно | async есть, но нужен свой исполнитель | продолжения есть, интеграция тяжелее | всё писать |
| ошибки | строка и позиция, цепочка вызовов функций | хорошие | хорошие | писать |
| песочница | по умолчанию ни файлов, ни сети, ни процессов | модули по выбору | Scheme со стандартной библиотекой | своя |
| serde ↔ значения | `rhai::serde::{to,from}_dynamic` — компоненты как карты без клея | свой `Value`, serde через обёртки | свой `SteelVal` | писать |
| размер, поддержка | чистый Rust, зрелый, давно 1.x | моложе, API меняется | нишевый | вся поддержка на нас |

Rhai выигрывает по главному: ожидание — это просто блокирующий вызов в
потоке скрипта, а значения мира ходят через serde. Цена — синтаксис со
своими зарезервированными словами (`with`, `spawn`, `call`, `until`
нельзя назвать функцией — пролог называет `spawn_entity`, `game`,
`wait_until`) и то, что `throw` в проверке ловится `try` (проверки не
«неуловимы»; случай `test` ловит сам).

## Чего не берём и почему

* **TCP.** Как в live-mcp: локальный порт открыт любому процессу любого
  пользователя машины; Unix-сокет 0600 в личной временной папке плюс
  токен — «только этот человек». На Windows сокета пока нет.
* **Чтение компонентов без `Serialize`.** Рефлексии в Rust нет; Debug
  дал бы строку, а не поля. Write-only с рецептом честнее.
* **Пикинг «что под точкой экрана», дерево UI, MCP-инструменты, поток
  событий/логов, `restore` снимка** — следующий этап (ниже).

## Ответы постулатам

1. **Скорость итерации.** Агент проверяет гипотезу в идущей игре за одну
   команду (`set`, `until`, `shot`), а сценарий — программой, а не
   пересборкой теста.
2. **Git.** В проекте ничего не появляется: сокет и карточка — во
   временной папке.
3. **Модульность.** Оболочка ничего не знает о мире; мир — модуль
   `world_control`, игра подключает одной строкой; ресурсы игры — её.
4. **Сеть.** Не касается; у каждого пира свой сокет.
5. **AI.** Главный: агент видит кадр окна, читает и правит мир, ждёт
   условия, пишет проверяемые программы. Тесты: `world_control` (запросы,
   поля, revert, snapshot/diff, until, registry), `shell::control`
   (токен, ответ цикла, версия), `shell::script` (команды, ожидания,
   случаи, строка ошибки), `scrap-cli world` (слова в аргументы),
   kitchen `the_world_control_reads_and_writes_the_kitchens_components`.
6. **Производительность.** Без флага — ноль. С ним кадр платит пустой
   `try_recv`; снимок окна ждёт GPU только когда попросили.
7. **Opinionated.** Один протокол для всех игр, одна команда `scrap world`.
8. **Батарейки.** `help` перечисляет всё, что игра умеет.

## Этапы

1. ✓ Сокет, команды оболочки, мир (query/get/set/add/remove/spawn/despawn/
   revert/snapshot/diff/until), ресурсы и команды игры, Rhai `script`,
   `scrap world`, kitchen и Not Divinity подключены (2026-11-12).
2. Дерево UI оверлея по кадрам (`ui.dump`, клик через настоящий ввод),
   пикинг по точке экрана, `restore` снимка, события (лог, ошибки)
   потоком, MCP-инструменты поверх тех же команд.
