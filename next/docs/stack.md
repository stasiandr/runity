# Стек и правила

Этот воркспейс живёт по правилу, обратному тому, что в `crates/`: **берём
готовое, своё пишем только там, где упёрлись в потолок**. Документ фиксирует,
что уже выбрано и почему, — чтобы решение не пересматривалось в каждой задаче
заново.

## Четыре правила, из которых следует остальное

**1. Движок — гость, никогда не хозяин.** `runity` не создаёт окно. Ему дают
поверхность, размер и поток событий ввода. Нативный Swift-редактор на macOS,
`UIViewController` на iOS и `Activity` на Android владеют своей поверхностью и
не отдадут её — одно правило закрывает все три случая, а десктопное окно
становится опциональной фичей `desktop-shell`, а не фундаментом.

**2. Типы wgpu не видны снаружи.** Публичный API `runity` оперирует своими
`MeshHandle`, `TextureHandle`, списком отрисовки. wgpu ломает API каждый
релиз (мы уже поймали это: egui 0.30 тянул wgpu 23, egui 0.34 тянет wgpu 29), а
отдельный Vulkan-бэкенд когда-нибудь захочется. И то и другое должно быть
внутренней заменой, а не переписыванием игры.

**3. Рантайм не линкует импортёры.** Всё, что умеет читать чужой формат,
живёт в `runity-import`. Игра на телефоне не несёт ни парсера OBJ, ни
декодера PNG, а загрузка перестаёт быть разбором.

**4. Сцены — исходник, ассеты — сборка.** Сцена остаётся текстом (RON),
потому что её правят люди и агенты, и `git` обязан показывать, что
изменилось. Ассет — бинарь, потому что его никто не правит руками: он
результат импорта. Это разные вещи, а не два вкуса одного.

## Ассеты: как в Unreal, по размеру — по нам

```
assets/            .obj/.gltf/.png/.wav — что дал набор или художник
  ↓ импорт (только редактор и CLI; здесь живут gltf, tobj, image)
library/           .rasset + .rimport
  ↓ кук (позже, под платформу)
pak/               один блоб, mmap
```

* `.rasset` — заголовок (магия, версия формата) плюс тело rkyv. Загрузка —
  чтение и каст, без разбора: вершины лежат в той раскладке, которую хочет
  GPU, боксы посчитаны при импорте.
* `.rimport` — настройки импорта и путь к исходнику, в RON. Без него импорт
  односторонний: нельзя ни пересобрать библиотеку, когда импортёр стал лучше,
  ни заметить, что исходник изменился. А раз это текст — диff показывает, кто
  и когда поменял масштаб.
* Ссылки — `AssetId`, не пути. Путь это факт про сегодняшний диск; id — факт
  про ассет. Id выводится из пути детерминированно, поэтому повторный импорт
  обновляет ассет, а не плодит сироту.
* Единицы и ориентация приводятся **при импорте**, один раз, а не масштабом
  на каждом инстансе в каждой сцене.

## Выбранное

| Слой | Взяли | Почему не альтернативу |
| --- | --- | --- |
| Графика | `wgpu` | единственный, кто даёт Metal на macOS/iOS, Vulkan/D3D12 на Win/Android без своих бэкендов; на iOS Vulkan не существует, только трансляция |
| Поверхность | `raw-window-handle`, оболочка на платформу | `winit` воюет с нативным хостом; оставлен за фичей для десктопной сборки |
| Физика | `rapier3d` | чистый Rust собирается под iOS/Android без C++-тулчейна. Jolt — если упрёмся в производительность |
| ECS | `hecs` | наименьшее, что работает; `flecs` держим в уме из-за его инспектора мира |
| Оболочка десктопа | `winit`, за фичей `desktop-shell` | не фундамент: движок и без неё работает, ему дают поверхность |
| Математика | `glam` | `nalgebra` всё равно придёт с rapier, конвертируем на границе |
| Формат ассетов | `rkyv` | zero-copy: в этом весь смысл «уже в удобном движку виде» |
| Формат сцен | `ron` | человекочитаемый и диффится — см. правило 4 |
| Импорт | `tobj`, дальше `gltf`, `image` | только в `runity-import` |
| Текст | `glyphon` (cosmic-text) | нужен шейпинг и кириллица |
| Звук | `kira` | игровой микшер поверх `cpal`, мобилки есть |
| Горячая перезагрузка | `subsecond` | патчит сам Rust, без второго языка и границы FFI |
| Мост в Swift | UniFFI (управление) + плоский C ABI (кадр) | UniFFI даёт заодно Kotlin для Android; горячий путь генерировать нельзя |
| Профилирование | `tracing` + Tracy | |

## Рендер без видеокарты

Кадр рисуется на машине без GPU и без дисплея: Vulkan имеет программную
реализацию (Mesa lavapipe), и wgpu берёт её как обычный адаптер. На Linux
хватает `mesa-vulkan-drivers`; на macOS всегда есть Metal, на Windows — WARP.

Это фундамент всей headless-работы: CI, golden-кадры и петля, в которой агент
меняет что-то и смотрит на результат. `Gpu::headless_blocking(true)` заставляет
взять программный адаптер даже там, где есть карта.

Одна оговорка, которую нельзя забыть: **программный кадр не совпадает с
кадром настоящей карты** побитово — правила растеризации, фильтрация и
плавающая точка различаются между реализациями. Значит, golden-изображение —
это эталон *одного адаптера*. Выбираем один (lavapipe в CI), пишем рядом,
какой именно, и сравниваем подобное с подобным. `Gpu::describe()` даёт эту
строку.

## Редактор

Только macOS, нативный Swift. Осознанная цена: кроссплатформенный редактор
некому использовать, пока пользователь один.

## Отложенное

**Сеть.** Не трогаем. Когда дойдём — пишем свою репликацию, а не берём
`renet`: если транспортом станет Steamworks, готовый стек всё равно
придётся разбирать. Транспорт должен быть трейтом (Steam на десктопе, UDP на
мобилках), репликация — нашей.

**Игровой UI.** Сейчас `docs/design/07-look.md` говорит, что HUD нет, но это
сегодняшнее решение, а не вечное. Поэтому фиксируем не тулкит, а **слой**:
экранный 2D-проход со своим списком отрисовки (квады плюс текстовые прогоны),
который рисуется после 3D. Две строки диалога пользуются им уже сейчас; полный
инвентарь потом будет пользоваться тем же. Виджетный слой не выбираем — это и
есть та часть, которая привязывает.
